## 3) User Journeys
1. **مريض يعرف ما يريد** (الأكثر شيوعًا على الموبايل): الرئيسية → «احجز موعدًا» (Quick Action أو الشريط السفلي الثابت) → تخصص → طبيب → تاريخ → وقت → بيانات → تأكيد.
2. **مريض يستكشف**: الرئيسية → الخدمات/الأقسام (بحث) → صفحة القسم (ماذا نقدم؟ لمن يناسب؟) → أطباء القسم → «احجز» (التخصص والطبيب محددان مسبقًا).
3. **حالة عاجلة**: أي صفحة → زر «اتصل» الثابت على الموبايل / رقم الهاتف في الهيدر. صفحات الطوارئ لا تعرض حجزًا بل اتصالًا مباشرًا.
4. **باحث عن الثقة**: الرئيسية → «لماذا مصر المحبة؟» (اعتماد GAHAR) → الأخبار بمصادرها الأصلية → عن المستشفى.

## 4) Design System
**الفكرة**: القوس (Arch) — إشارة هادئة لعمارة الصعيد والكنيسة — يظهر في إطار صورة الـHero وخلفيات بطاقتي «الاعتماد» والـCTA. كل ما عداه هادئ.

| Token | Light | Dark | الاستخدام |
|---|---|---|---|
| `--primary` Nile Teal | #0B5D5B | #4FB3AC | الأزرار، الروابط، الحالة النشطة |
| `--ink` | #0F2A2E | #E8F1EF | العناوين والنصوص |
| `--bg` / `--surface` | #F7F9F8 / #FFF | #0A1718 / #102223 | الخلفيات |
| `--accent` Honey | #B7812A | #D9A650 | شارات «بانتظار الاعتماد» فقط تقريبًا |
| success / danger | #1E7A4C / #B3261E | — | حالات النماذج |

- **الخطوط**: Readex Pro (عناوين 500–600) + IBM Plex Sans Arabic (نصوص 400–600). مقياس: 13 / 15 / 17 (أساسي) / 20 / 28 / 40 / 60px مع `clamp`. ارتفاع السطر 1.85 للعربية.
- **Spacing**: قاعدة 4px (4, 8, 12, 16, 24, 32, 48, 72, 104).
- **Radius**: 8 / 14 / 22 / pill / arch.
- **Shadows**: 3 مستويات فقط، تُستخدم عند الرفع (hover، بطاقات عائمة).
- **Buttons**: Primary · Ghost · Soft · Small · Block — ارتفاع لمس ≥ 44–48px، حالات hover/active/focus/disabled.
- **Cards**: قسم/خدمة (أيقونة + CTA يظهر عند hover، ظاهر دائمًا على اللمس)، طبيب، خبر.
- **Forms**: Label مرئي دائمًا، hint، رسالة خطأ مرتبطة بـ`aria-describedby`، تحقق عند blur وsubmit، رقم موبايل مصري.
- **Icons**: مجموعة SVG واحدة مخصصة (24px، خط 1.75) — لا مكتبات.
- **Motion**: 140 / 260 / 520ms بمنحنى `cubic-bezier(.22,1,.36,1)`. تحميل الـHero متسلسل، كشف الصورة بقناع القوس، reveal عند التمرير (المحتوى مرئي افتراضيًا + failsafe)، خط رحلة المريض يمتلئ، انتقال صفحات. يحترم `prefers-reduced-motion` بالكامل.

## 5) Architecture
```
src/
  styles/     tokens.css · base.css · components.css · sections.css
  data/       site.js · departments.js · services.js · doctors.js · content.js   ← كل المحتوى
  services/   api.js      ← طبقة البيانات والحجز (mock ↔ remote)
  utils/      core.js     ← icons · SEO · motion · formatting
  components/ ui.js       ← Header, Footer, Cards, Media, CTA…
  pages/      home · catalog · people · booking
  main.js     ← router + app shell
public/       robots.txt · sitemap.xml
build.mjs     ← يدمج كل شيء في dist/index.html (بدون أي dependencies)
```
- **الأداء**: بدون Frameworks أو مكتبات — HTML/CSS/JS ≈ 136KB غير مضغوط (≈ 39KB gzip)، خطان من Google Fonts مع `display=swap`، صور `loading="lazy"` و`decoding="async"` وصورة الـHero `fetchpriority="high"`.
- **الحجز**: `Api` في `services/api.js` هو الواجهة الوحيدة. غيّر `API_CONFIG.mode = "remote"` و`baseUrl` — العقد (Endpoints) موثق في رأس الملف.
- **الإنجليزية لاحقًا**: كل النصوص في `data/`، الاتجاه عبر `SITE.dir`، وCSS مبني بالكامل على خصائص منطقية (`inset-inline`, `padding-inline`) فيعمل LTR دون إعادة كتابة.

## 6) الانتقال إلى الإنتاج (موصى به)
النموذج الحالي يستخدم Hash routing ليعمل كملف واحد في أي مكان. للإطلاق الفعلي وتحقيق SEO كامل:
1. **Next.js (App Router) + TypeScript** مع Static Generation لكل صفحة — كل `render()` يصبح Server Component، وكل `UI.*` يصبح React component، و`data/` تنتقل كما هي إلى Headless CMS (مثل Sanity أو Strapi) ليعدّلها فريق المستشفى.
2. الروابط تصبح `/departments/dialysis` (نفس الـsitemap)، و`meta()` لكل صفحة تتحول إلى `generateMetadata`، وJSON-LD (Hospital, MedicalClinic, Physician, NewsArticle) جاهز.
3. الصور: `next/image` بصيغ AVIF/WebP.
4. تضمين Google Maps iframe بعد تحديد الإحداثيات الدقيقة.
5. ربط الحجز بنظام المستشفى + reCAPTCHA/Rate limiting + إشعار SMS.

## 7) تحديث الإصدار الثاني
- **ثنائي اللغة**: العربية هي الواجهة الافتراضية (`#/…`) والإنجليزية تحت `#/en/…` مع زر تبديل في الهيدر والقائمة والفوتر، وتبديل تلقائي لاتجاه الصفحة (RTL/LTR) وhreflang وsitemap ثنائي. كل النصوص في `L("عربي", "English")` داخل `src/data` و`src/utils/i18n.js`.
- **الهوية**: الألوان مشتقة من الشعار الرسمي (أزرق #0F6CB4، سماوي #4DB3E6، برتقالي #C4562B للاستخدام المحدود)، والشعار في الهيدر والفوتر وأيقونة التبويب. الشعار الرسمي «صحتكم مسئوليتنا… ورعايتكم مهمتنا» مأخوذ من صورة الغلاف.
- **الصور**: صورة المبنى الرسمية مقسمة إلى 4 لقطات (`src/assets/img`) مستخدمة في الـHero وعن المستشفى والمرافق والأخبار والتواصل. لم يكن ممكنًا جلب صور Stock (مواقع الصور محجوبة في بيئة العمل) ولا توليد صور (رصيد Gamma = 0)، لذلك الأقسام والأطباء تستخدم لوحات بصرية مصممة بألوان الهوية. لإضافة صورة حقيقية: ضع ملف WebP في `src/assets/img` واكتب اسمه في حقل `image` أو `photo`.
- **الاتصال**: كل أرقام الهاتف روابط `tel:` فعلية. داخل معاينة Claude (إطار محمي) تظهر نافذة اتصال بها زر «اتصل الآن» ونسخ الرقم.
- **الحجز**: 4 خطوات — التخصص ← الطبيب ← الموعد المفضل (اختياري) ← **اتصل للحجز** مع نص جاهز يقوله المريض لموظف الحجز.
- **الأرقام**: 144 سريرًا، 7 طوابق، 4 غرف عمليات، 11 جهاز غسيل، 9 حضانات، ~600 مريض يوميًا — متطابقة في الوطن والدستور وفيتو (13 مايو 2026)، وتظهر كعدادات متحركة مع رابط المصدر.
- **الأخبار**: 5 أخبار حقيقية، كل خبر بصفحة داخلية + رابط المصدر الأصلي + تنقل للخبر السابق/التالي. تم فحص كل الروابط الداخلية (88 رابطًا) بلا أخطاء.
- **الحركة**: انتقال صفحات (خروج/دخول)، عنوان Hero يظهر سطرًا بسطر، كشف صورة المبنى مع Ken Burns وParallax خفيف، شريط تقدم التمرير، هيدر ينكمش ويختفي عند النزول، Reveal متدرج للبطاقات، كشف الصور بقناع، عدادات، Spotlight يتبع المؤشر على البطاقات، رنين أيقونة الهاتف، انتقال خطوات الحجز حسب الاتجاه، تبديل لغة بتلاشي ناعم — وكلها تُلغى مع `prefers-reduced-motion`.
- **المراجعة**: 17 مسارًا × لغتين × مقاسين (1440 و390) — بدون أخطاء JavaScript، بدون تمرير أفقي، بدون نصوص عربية متبقية في النسخة الإنجليزية.

## 8) الإصدار الثالث — لوحة التحكم (CMS)
- **Decap CMS 3.16** على `/admin` بواجهة عربية كاملة (ترجمة مخصصة في `admin/locale-ar.js`) ودليل للمحررين في `/admin/guide.html`.
- **المحتوى انتقل من الكود إلى `content/`** (JSON). الموقع لم يعد يحتوي أي نصوص محتوى داخل `src/` — فقط `src/data/index.js` يشكّل المحتوى للعرض.
- **كل حقل ثنائي اللغة** `{ "ar": "", "en": "" }` بخانتين متجاورتين في اللوحة.
- **الحقول الفارغة** (مثل الرؤية، البريد، المؤهلات) تظهر على الموقع بشارة «بانتظار الاعتماد» بدل `TBD(...)` القديمة.
- **الحماية**: `scripts/content.mjs` يفحص: المعرّفات، التكرار، الروابط بين الأطباء/الأقسام/الخدمات/الفئات، صيغة المواعيد وترتيبها، وجود الصور، أرقام الهاتف، التواريخ، روابط المصادر. يعمل داخل البناء على Netlify وفي GitHub Actions.
- **نظام المراجعة (Editorial Workflow)** مفعّل: مسودة ← قيد المراجعة ← جاهز ← نشر، مع Deploy Preview قبل النشر.
- **الصور** في `content/uploads` وتُقدَّم على Netlify عبر Image CDN.
- **تم الاختبار محليًا** عبر `decap-server`: فتح اللوحة، قائمة الأطباء، تحرير طبيب وقسم، نموذج إضافة طبيب جديد، حفظ تعديل وظهوره في الموقع بعد البناء، وإيقاف البناء عند إدخال موعد غير صالح. تسجيل الدخول الحقيقي عبر GitHub OAuth لا يمكن اختباره إلا بعد النشر على Netlify.

## 9) نسخة Vercel
- استبدال `netlify.toml` بـ `vercel.json` (البناء، الهيدرز، تحويل الروابط النظيفة مثل `/about` إلى الصفحة، إعدادات الصور).
- تسجيل الدخول للوحة عبر دالتين على Vercel: `api/auth.js` و`api/callback.js` (GitHub OAuth مع حماية state، والـ Client Secret يبقى على السيرفر). تم اختبار: تحويل زر الدخول إلى GitHub، نجاح تبادل الكود، رفض الكود الخاطئ، ورفض state غير مطابق.
- اكتشاف المستودع والفرع والرابط تلقائيًا من متغيرات Vercel (`VERCEL_GIT_REPO_OWNER/SLUG`, `VERCEL_PRODUCTION_BRANCH`, `VERCEL_PROJECT_PRODUCTION_URL`).
- ضغط الصور اختياري عبر `VERCEL_IMAGES=1`.
